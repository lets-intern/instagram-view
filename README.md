# Draftroom · 계정별 게시물 시안 검토

프로필을 저장해 두고 계정별로 카드뉴스·릴스 초안을 계속 등록하는 웹 도구입니다. 초안별 검토 전용 링크로 거래처에 공유할 수 있습니다. **의견 작성·수집 기능은 이번 범위에서 제외**했습니다.

## 실행

Node.js 24 이상이 필요합니다.

```sh
npm ci
npm start
```

기본 포트는 3000입니다. 시작 출력의 **Editor** 경로는 편집자에게만 전달하세요. **Reviewer** 경로는 전체 계정을 보는 팀 검토용입니다. 키는 첫 실행 시 생성되어 `data/state.json`에 저장됩니다.

1. 계정 프로필에서 이름·사용자명·표시 이름·프로필 사진·인증 배지를 설정합니다.
2. ‘새 초안’으로 해당 계정에 게시물을 추가합니다. 프로필은 새 초안에도 자동 적용됩니다.
3. 이미지·영상을 추가하고 캡션과 연출값을 입력합니다. 변경 사항은 자동 저장됩니다.
4. 계정 선택과 초안 탭으로 전환합니다. 프로필 변경은 그 계정의 기존 초안에도 반영됩니다.
5. ‘거래처 링크’로 현재 초안만 공유합니다. 로그인 없이 열람할 수 있고 편집할 수 없습니다. 다른 초안·계정·미디어에는 접근할 수 없습니다.
6. 필요하면 ‘HTML 파일’로 현재 초안 또는 현재 계정의 모든 초안을 미디어 포함 단일 파일로 내려받습니다.

링크를 가진 누구나 허용된 시안을 볼 수 있으므로 편집·팀 링크를 거래처에 전달하지 마세요. 계정 로그인·역할 관리·링크 만료/회수 UI는 없습니다.

## 저장과 호스팅

```sh
DATA_DIR=/persistent/draftroom PORT=3000 npm start
```

내부·거래처 공유 링크에는 **Node 서버 + 영구 디스크 + 공개 HTTPS 주소**가 필요합니다. 정적 호스팅만으로는 같은 미디어를 다른 기기에 제공할 수 없습니다. 호스팅 공급자는 아직 선택·배포하지 않았습니다.

- `DATA_DIR`의 `state.json`과 `media/`를 함께 백업·복원합니다. 새로고침·서버 재시작 후에도 계정·초안·미디어·링크가 유지됩니다.
- 단일 프로세스용 JSON 메타데이터 저장소입니다. 여러 서버가 같은 JSON 파일에 동시에 쓰는 배포는 지원하지 않습니다.
- 업로드는 스트리밍하며 파일당 **100MiB(104,857,600바이트)**까지 허용합니다. 프록시 요청 크기 한도도 최소 100MiB 이상으로 설정하고 충분한 업로드 타임아웃을 둡니다.
- 영상 재생용 Range 요청과 변경 사항 동기화용 SSE를 통과시킵니다. SSE 응답 버퍼링을 끕니다.
- 영상 3개는 원본만 300MiB이며, HTML은 Base64로 약 33% 커집니다. 디스크·브라우저 메모리·메신저 첨부 한도를 고려해야 합니다. 압축이나 더 작은 업로드 제한은 적용하지 않습니다.

## 지원 기능

- 계정 추가·프로필 공통 설정·계정별 초안 목록. 초안 생성·이름·상태·삭제·전환.
- 카드뉴스 최대 20개: JPG/PNG/MP4/MOV 혼합, 드롭·클릭·다중 선택, 업로드 진행률, 개별/전체 삭제, 순서 변경.
- 릴스: 영상 1개, 선택적 커버·오디오 표기. 피드 4:5 크롭, 릴스 탭 9:16, 자동 재생·탭 일시 정지·음소거 해제.
- 390×844 폰 프레임, 홈 피드·게시물 상세·릴스 탭, 스와이프·점·카운터, 비율·cover/contain·폰 다크 모드.
- 캡션 즉시 반영·더 보기·해시태그/멘션 강조·글자/해시태그 한도 경고. 좋아요/댓글 수는 미리보기 연출값입니다.
- 편집 모듈을 제외한 독립 HTML 내보내기. 외부 폰트·라이브러리·API 없이 이미지·영상 재생. 큰 영상은 조각별 Base64로 삽입하고 Blob으로 복원합니다.
- 로고·워드마크 대신 일반 도형 사용. 내부 검토용 표기와 모바일 레이아웃.

MOV의 실제 재생은 브라우저의 코덱 지원에 달려 있습니다. 미지원 시 오류를 표시합니다. 영상 편집·트랜스코딩·실제 게시·프로필 그리드는 포함하지 않습니다.

## 검증

```sh
npm test
```

계정 프로필 공통 적용, 계정·초안 분리, 거래처 링크 범위, 편집 차단, 변경 알림, 서버 재시작 지속성, 잘못된 설정 거부를 통합 검증합니다.

100MiB 파일 검증용으로 정상 H.264 MP4에 패딩을 붙여 전송 바이트 수를 정확히 맞춥니다.

```sh
ffmpeg -f lavfi -i color=c=0x6379db:s=360x450:d=2 -c:v libx264 -pix_fmt yuv420p -movflags +faststart /tmp/draftroom-100mb.mp4
truncate -s 104857600 /tmp/draftroom-100mb.mp4
VIDEO_FIXTURE=/tmp/draftroom-100mb.mp4 npm test
VIDEO_FIXTURE=/tmp/draftroom-100mb.mp4 node scripts/browser-smoke.mjs
```

브라우저 검사는 Playwright와 `/usr/bin/chromium`을 사용합니다(`CHROMIUM_PATH`로 변경 가능). 임시 데이터와 별도 서버를 자동 생성·정리하며 3140·3138 포트를 사용합니다. HTML과 데스크톱·모바일 캡처는 `/tmp/draftroom-review.html`, `/tmp/draftroom-desktop.png`, `/tmp/draftroom-mobile.png`에 남깁니다.

### 검증 범위와 남은 사항

API에서 실제 100MiB 영상 3개 저장·구간 요청·재시작 복원과 계정/초안 권한을 확인했습니다. 브라우저 검사는 계정 프로필 재사용, 혼합 캐러셀, 릴스, 거래처 링크와 편집 UI 부재, 미디어 포함 HTML 독립 재생, 모바일 가로 넘침을 검증합니다.

관리형 Chromium 정책은 `file://` 탐색을 차단합니다. 내보낸 HTML은 임시 로컬 서버에서 읽은 후 네트워크를 끊고 독립 동작을 검증합니다. **Chrome/Safari/Edge에서 파일을 직접 여는 검사와 공개 HTTPS 주소를 통한 실제 다른 기기 검토는 아직 완료하지 않았습니다.** 배포 및 이 검증 전에는 출시 완료로 간주하지 마세요.

## 배포용 컨테이너

런타임 외부 패키지 없이 실행되는 Docker 이미지를 제공합니다. `/healthz`는 키를 요구하지 않는 상태 확인 주소입니다.

```sh
docker build -t draftroom .
docker run -d --name draftroom -p 3000:3000 -v draftroom-data:/data --restart unless-stopped draftroom
```

`/data` 볼륨을 생략하면 안 됩니다. 배포 서비스에서도 이 경로에 영구 디스크를 연결해야 합니다. 편집 링크는 최초 시작 로그에서 확인하며 키를 공개 저장소에 올리지 않습니다. 이 컨테이너는 배포 패키지이며, 빌드 성공 자체가 공개 HTTPS 배포 완료를 뜻하지 않습니다.

## GitHub Pages + Supabase

대상 프로젝트는 `https://nfnhapavxiyobacvdrym.supabase.co`입니다. `supabase/schema.sql`은 `draftroom_*` 테이블·RPC와 `draftroom-media` 비공개 버킷만 구성합니다. 기존 프로젝트의 다른 테이블·버킷은 사용하지 않습니다. 의견 기능은 없습니다.

자동 배포는 GitHub 저장소의 Actions secret `SUPABASE_ACCESS_TOKEN`을 사용합니다. Pages Source를 GitHub Actions로 설정한 뒤 main에 푸시하면 연결·배포·실제 100MiB 검증이 실행됩니다. 로컬에서 관리 토큰이 안전하게 주입된 경우에만 다음 수동 명령도 사용할 수 있습니다.

```sh
python3 scripts/deploy-supabase.py --publish
```

스크립트는 프로젝트 확인, SQL 적용, 첫 워크스페이스 생성, 공개 anon 키만 포함한 `public/config.js` 생성, GitHub Pages 활성화, 코드 커밋·푸시를 처리합니다. 기존 원격 커밋을 강제로 덮어쓰지 않습니다. 초기 편집·팀 검토 키는 Git에서 제외되는 `data/deployment-links.json`에 보관합니다. 관리 토큰과 service-role 키는 프런트엔드에 포함하지 않습니다.

스토리지 객체당 5MiB로 나누므로 원본 100MiB도 20개 객체로 저장됩니다. 로딩 시 Blob으로 복원하며 전송 오류는 재시도합니다. 계정 프로필·초안은 Supabase DB에 저장되고 거래처 링크는 해당 초안과 참조된 미디어만 읽습니다. 이 모드는 5초 간격으로 변경을 확인합니다. 검토 후 초안을 삭제하면 거래처 링크도 더 이상 접근할 수 없습니다. 물리적 미디어 정리·장기 보관·공간 최적화는 이번 범위에서 다루지 않습니다.

`npm test`에는 100MiB 원본을 20개 조각으로 전송·복원해 SHA-256이 같은지 확인하는 어댑터 테스트가 포함됩니다. SQL은 격리된 PostgreSQL에서 `supabase/test.sql`로 권한·계정 분리·미완료 업로드 거부를 검증했습니다. 실제 Supabase 프로젝트에서의 Storage/CORS·브라우저 재생과 GitHub Pages 공개 배포 검증은 관리 권한 연결 후 진행해야 합니다. 아직 공개 배포가 완료된 상태는 아닙니다.

자동 배포의 초기 편집 링크는 저장소에 공개된 RSA 공개키로 암호화해 `supabase/deployment-access.enc`에 기록합니다. 복호화용 개인키는 이 작업 환경의 Git 무시 경로 `data/deploy-private.pem`에만 있으며, 브라우저나 GitHub 저장소에 게시하지 않습니다. 실제 배포 성공 여부는 Actions 실행 및 `deployment-status.json`으로 확인합니다.

### 영상 첫 재생 속도

클라우드 영상은 전체 Blob을 완성할 때까지 기다리지 않고 서비스 워커가 원본의 HTTP Range 요청을 5MiB 저장 객체에 연결합니다. 필요한 구간부터 순서대로 스트리밍하고 최대 3개 조각을 미리 받습니다. 뒤쪽 메타데이터 탐색·재생 중 탐색도 원본 바이트 위치를 유지합니다. 캡션·미리보기 UI는 로딩 중에도 사용할 수 있습니다. 서비스 워커가 지원되지 않거나 실패하면 4개 조각씩 병렬 다운로드하는 Blob 방식으로 복귀합니다. 오프라인 HTML 내보내기는 원본 파일 전체를 포함합니다.

`node scripts/stream-smoke.mjs`는 100MiB 영상의 뒤쪽 조각을 의도적으로 막은 채 첫 프레임이 재생되는지 확인하고, suffix Range와 워커 재시작 복구도 검증합니다. 실제 공개 배포의 첫 프레임 시간·그때까지 받은 바이트는 Actions가 `deployment-status.json`에 기록합니다.

저장 조각 하나(5MiB)가 끝날 때까지도 기다리지 않도록, 스토리지 응답의 작은 네트워크 블록을 즉시 영상 재생기로 전달합니다. 로컬 브라우저 검증에서는 첫 64KiB만 제공하고 나머지 응답을 막아둔 상태에서도 100MiB MP4가 재생됐습니다.
